## 2026-03-26 — list-subscription: Subscribe to curated lists, toggle on/off, multi-list learning

**Completed:**
- Added 4 new query functions in `lib/db/queries/word-list-items.ts`: `isUserSubscribed`, `subscribeToList`, `unsubscribeFromList`, `getOrCreateUserList`
- `subscribeToList`: creates subscription record, copies source list items into user's personal list (copy-on-write for text/position, shared audio_asset_id reference), creates matching categories, creates initial user_progress entries for all copied items. Sets canonicalWordId to source item ID for traceability
- `unsubscribeFromList`: finds copied items via canonicalWordId matching, archives progress entries (sets archived_at), deletes copied items from user's list, removes subscription record
- `getOrCreateUserList`: ensures each user has a personal list for receiving copied items
- Created `app/api/lists/[id]/subscribe/route.ts` — GET (check subscription status), POST (subscribe with copy-on-write), DELETE (unsubscribe with archive)
- POST validates: list exists, list is public, not own list, not already subscribed. Returns { subscribed: true, copied: N }
- DELETE validates: currently subscribed. Returns { subscribed: false, archived: N }
- Updated `app/lists/ListSidebar.tsx` — curated lists now show toggle switches for subscribe/unsubscribe. Toggle state tracked via subscribedListIds Set. Toggling disabled during in-flight request
- Updated `app/lists/page.tsx` — loads subscription status for all public lists on mount, passes subscribe/unsubscribe handlers to sidebar
- Created `app/api/lists/__tests__/subscription.test.ts` — 13 tests covering auth, validation (404, 403, 400, 409), subscribe flow, unsubscribe flow, user list creation
- All 183 tests pass, build succeeds

**Decisions:**
- Copy-on-write creates categories in user's list matching source list categories (not reusing source category IDs)
- Items copied in batch (100 per insert) with initial progress entries (stageIndex=0) for immediate availability in word stream
- Subscription status loaded per-list via individual GET calls (simple, scales fine for small number of public lists)
- Unsubscribe matches copied items by canonicalWordId → source item IDs (robust even if user has edited the text)
- Personal list auto-created with default cs→vi language pair on first subscription

## 2026-03-26 — audio-infrastructure: Arweave storage, R2 CDN cache, Cloudflare Worker proxy for media and BYOK key safety

**Completed:**
- Created `lib/audio.ts` — audio generation and storage abstraction:
  - `computeContentHash(text, language, provider)` — SHA-256 content-addressed hash for dedup
  - `googleTTS(text, language)` — Google Cloud TTS API (MP3, language code mapping)
  - `elevenLabsTTS(text, language, encryptedKey, voiceId)` — ElevenLabs BYOK via Cloudflare Worker proxy
  - `uploadAudio(audio, contentHash, metadata)` — uploads to Worker endpoint (Arweave primary, R2 fallback), falls back to local dev stub
  - `getAudioUrl(contentHash)` — returns Worker URL or local API URL for dev
- Created `lib/db/queries/media-assets.ts` — CRUD for media_assets table:
  - `findMediaByHash` / `findMediaByHashes` (single + batch lookup by content_hash)
  - `createMediaAsset` — inserts with dedup-safe onConflictDoNothing
  - `linkAudioToItem` / `batchLinkAudioToItems` — sets audio_asset_id + audio_status on word_list_items
  - `getMediaAsset` — by ID lookup
- Created `app/api/audio/generate/batch/route.ts` — POST endpoint: DB dedup first (findMediaByHashes), generates remaining in parallel batches of 3, returns per-item results with source (dedup/generated)
- Created `app/api/audio/[hash]/route.ts` — GET endpoint: redirects to Worker URL if configured, otherwise returns metadata JSON for local dev
- Created `lib/audio-prefetch.ts` — client-side prefetch utility injecting `<link rel="prefetch">` tags for upcoming audio URLs (max 10)
- Added audio tests in `app/api/audio/__tests__/audio.test.ts` — 12 tests covering auth, validation, dedup, generation, failure handling, mixed results, max items limit, audio serving
- Exported media-assets queries from `lib/db/queries/index.ts`
- All 195 tests pass, build succeeds

**Decisions:**
- Content-hash = SHA-256 of `${text}|${language}|${provider}` — deterministic, enables cross-user dedup
- Worker URL configured via `AUDIO_WORKER_URL` env var; when absent, local dev fallback returns metadata JSON
- ElevenLabs calls route through Cloudflare Worker proxy so BYOK keys never touch Next.js server
- Upload fallback chain: Worker (Arweave → R2) → local dev stub (no-op)
- Batch generation uses parallel windows of 3 to avoid rate limiting
- Max 200 items per batch request
